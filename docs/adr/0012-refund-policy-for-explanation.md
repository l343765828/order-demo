# 退款资格由程序规则判断，政策用于解释

2026-11-28，确认依据可信订单状态和统一的程序规则判断退款资格。退款办理沿用本次办理授权、订单归属、事务和幂等校验。取消新退款提交前的政策检索、证据核验及政策核验事件持久化要求，避免政策服务故障阻断符合条件的模拟退款。

新流程与正式政策 RF-013 新版协调生效。生效后，本决定取代 [ADR-0009](0009-refund-policy-evidence-before-dispatch.md) 及 [ADR-0004](0004-refund-agent-storage-boundaries.md) 中续办前重新检索政策的要求。政策咨询和解释沿用 [ADR-0010](0010-refund-policy-publication-and-evidence.md) 中的政策发布、版本快照和引用核验。

## 开发环境切换

确认目标开发库符合新版表结构，停止使用该库的 Agent 和 MCP 服务，确认在途写入结束。发现旧表结构时暂停切换，另行确认处理方式。切换时使用现有演示数据重置流程，清空该库中的退款演示订单、模拟退款、退款提交、会话、摘要、消费者偏好和检查点，重新装载种子，再从新会话进入新流程。

目标开发库的旧退款提交均为测试数据。确认在途写入结束后，仍处于 `pending` 或 `unconfirmed` 的提交随演示数据一并清空，无需逐笔核实其旧结果。切换后新产生的未决提交继续按 [ADR-0007](0007-refund-unconfirmed-dispatch.md) 核对并拦截重复办理。

同一次切换清理目标开发环境的 `refund_policy_events_dir` 中由旧流程生成的退款政策核验 JSONL。政策发布目录、Milvus 索引、其他演示数据和仓库验收记录继续保留。旧币种迁移和旧检查点转换随旧格式退出。当前格式的会话恢复、退款结果核对、未决提交拦截和幂等继续适用。

## 办理授权和政策说明

办理指令须在本轮消息中写明唯一的目标订单号。消费者在看完政策后只说“请帮我退”或“帮我退刚才那单”时，请消费者在一条办理指令中明确写出订单号。

订单符合退款条件且消费者已明确授权办理时，调用现有退款服务，按业务回执回复。沿用现有退款提交记录、幂等处理和结果核对机制，提交前因资格被拒绝的原因通过现有结构化日志记录。

消费者明确授权办理并附带询问政策依据时，按业务核验和真实回执处理退款，回复附上已核实的依据。政策检索失败或依据不足时，保留真实业务结果并说明依据暂时无法核实。消费者明确表示看完条款再决定时，先回答政策问题，收到消费者明确办理指令后才提交退款。

消费者把查到适用的正式条款设为办理条件时，先出示已经核验的条款，收到消费者明确办理指令后才提交退款。无法核实适用的正式条款时，说明依据暂时无法核实并结束本轮。
