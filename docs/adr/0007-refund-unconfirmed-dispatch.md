# 同一订单的退款结果待核对时暂停新的提交

2026-11-19，用户确认前一次办理的结果待核对时须拦截该订单的新提交，明确收到继续指令也先核对原结果。这样可避免在原请求仍可能产生退款时把查无记录误判为失败；代价是该订单须等到找到原退款，或确认旧提交未产生且已无法再产生退款后才能继续，其他订单照常办理。持久状态与解除条件见[数据库表结构](../../.scratch/refund-agent-all-tech-demo/database-design.md)。

2026-11-19，用户确认由演示维护命令与退款写入锁定同一提交记录。有退款则返回原结果，查无退款则在该事务中关闭旧提交。关闭使迟到的旧请求无法执行。

2026-11-19，用户确认旧提交已核实无退款并关闭后，原会话可以在消费者明确继续后恢复待办，新会话可以在消费者明确指定同一订单并要求办理后受理新的退款申请。两种情况都依据当前会话的指令重新校验并使用新幂等键。旧提交未决时，所有会话均须先核对原结果。
