# 04 协调政策发布与开发环境验收

Status: ready-for-agent

Blocked by: [03 处理主动询问政策和办理授权](03-handle-explicit-policy-requests-and-authorization.md)

## 要实现的行为

协调退款流程与 RF-013 新版生效，在目标开发环境从重置后的演示数据和新会话验收整条链路。交付应用流程、正式政策、业务集成验证和可复查的结果。参见[改造规格](../spec.md#测试决定)。

按 [ADR-0012 的开发环境切换约定](../../../docs/adr/0012-refund-policy-for-explanation.md#开发环境切换)，先确认目标开发库符合新版表结构，停止 Agent 和 MCP 服务并确认在途写入结束。旧演示数据重置包括仍处于 `pending` 或 `unconfirmed` 的测试提交。同期清理目标开发环境中由旧流程生成的政策核验 JSONL。

## 验收标准

- [x] RF-013 新版与应用办理行为一致，记录用于验收的程序版本、生效政策版本和协调切换顺序。验证正式政策版本快照和引用来源。
- [x] 对明确的目标开发环境使用现有演示数据重置流程并重新装载种子。核对旧提交已清空、旧政策核验 JSONL 已清理，以及政策发布目录、Milvus 索引和其他演示数据保留。从新会话验证查单、退款、只读补号接续与新流程的未决退款防重。
- [x] 从冷启动验证政策组件不可用的情形。合格且已明确授权的模拟退款仍可办理，已确认的业务拒绝仍能说明原因，政策咨询回复依据不可核实。
- [x] 在隔离 MCP 和业务库执行端到端验证，覆盖提交前拒绝、事务内拒绝、重复办理、并发、事务失败及结果待核对。运行完整测试集和项目适用的代码质量检查。
- [x] 更新相关中文 README、架构和流程说明。记录关键状态变化、调用链及调用次数变化，保存完整验证命令、结果和待复核事项。
- [x] 新流程通过订单号来源、只读补号和办理授权回归。订单号提取工单 02 的独立实模验收按自己的固定基线记录。
