# 退款 Agent：聊天上下文压缩设计

性质：已纳入 2026-11-19 用户确认的设计基线，退款应用压缩尚未实施；具体预算和适配器由实施者核实  
关联：[主设计](spec.md)、[存储与记忆](storage-memory.md)、[术语表](../../GLOSSARY.md)

## 1. 已确认的前提

- 原始聊天完整保存在 MySQL；正常重启保留数据，仅显式重置才恢复演示数据。
- 同会话记忆和图状态持久化到 MySQL；跨会话记忆只保存消费者明确要求记住的稳定偏好。
- 模拟订单与退款记录也在 MySQL，政策向量在集群 Milvus。
- 原始聊天、模型本次输入、会话摘要与消费者长期偏好属于不同对象。

用户已确认本轮 Q4：由外层 LangGraph 按实际 token 预算自动压缩较早对话、保留近期完整交互，工具调用与对应结果成对处理；摘要失败且无法安全装入必要上下文时，暂停本轮、保留数据，不继续执行退款。用户也确认 Q5 的长期偏好查看、更正、删除与最新明确指令优先规则。

## 2. 要解决的问题

完整留库不代表每次把全部聊天发送给模型。多轮对话、工具定义与返回结果、计划、检索条款及模型输出预留都会占用上下文；长对话可能超出模型服务允许的窗口，即使数据库可以保存全部原文也不能改变这一限制。

本次模型输入按以下内容组合，并按节点实际职责选取：

1. 固定角色规则及本次可用工具 / Schema。
2. 当前消费者问题与最近若干个完整交互回合。
3. 较早对话的退款会话摘要；尚无需要压缩的历史时可为空。
4. 当前订单、待办、授权、取消或换单状态、计划进度等结构化状态。
5. 本次所需的最新工具事实、Milvus 政策证据和相关显式长期偏好。

压缩只改变当次提供给模型的历史表示，不删除聊天原文，不清理业务记录，不把会话摘要自动写入长期偏好。

## 3. 压缩流程

每次模型调用前先计入系统规则、工具 / Schema、消息、摘要、结构化上下文和检索片段的 token，并预留模型生成预算和边界余量。压缩触发值取决于实际部署服务的上下文上限、所选 tokenizer 和具体角色的输出需求，不直接套用模型宣传窗口、固定聊天轮数或其他模型的默认阈值。

在接近预算前自动压缩较早的完整交互回合，保留近期原始消息；压缩结果再计数并核验后才用于后续调用。摘要自身生成也要受窗口限制，可根据覆盖区间分段更新；不能把已经超窗的全部历史直接交给同一个模型生成摘要。

工具调用与对应观察作为完整交互单元保留或压缩，不从中间切开。尚未完成的工具往返、当前用户输入及其解释所需的近期消息不作为旧历史随意丢弃。较早的冗长工具原文可以从本次输入移除，过程事件按 `trace_id` 查询结构化日志，当前有效事实从业务服务重新查询。

## 4. 摘要的边界

会话摘要可保留讨论主题、已解释问题、信息补充经过和需要澄清的事项，并记录原始消息覆盖范围。当前订单与授权、取消状态、已经发生的退款结果及计划进度由独立结构化状态维护，不通过摘要重新推导。

例如，消费者先要求退款，后来取消，压缩后的叙述即使遗漏取消，也不能恢复原办理授权；消费者从 DEMO-1001 改退 DEMO-1002 后，摘要不能让执行器沿用旧订单事实。执行前仍重新核对当前订单、有效授权、实际状态和唯一退款记录。

摘要不提升为系统指令，不授予工具权限，也不能替代 Milvus 本次检索到的政策依据。原文和摘要保留来源标识；确需核对早期表述时，可以按会话和消息范围读取原文，具体召回机制留给实现者。

消费者已经删除或更正的长期偏好，不能由旧摘要、旧原文或旧 checkpoint 再次启用。构造模型输入时，从当前有效偏好记录读取最新值；历史中的偏好表述只代表当时发生过的对话，不构成新的记忆写入指令。当次临时表达要求可以影响本轮回复，但只有明确的长期偏好指令才修改持久化偏好。

## 5. LangGraph 与 DeepAgent 的职责

消费者会话的压缩由外层 LangGraph 调用前的上下文组装节点统一负责，维护一个版本化会话摘要。意图理解与 Planner / Replan 按其所需范围使用该摘要及近期消息；DeepAgent 和子 Agent 继续只接收当前任务相关上下文。该所有权决定见 [ADR-0005](../../docs/adr/0005-refund-conversation-compression-owner.md)。

DeepAgent 已有摘要中间件能力，但不能假设其默认阈值适合自托管 Qwen 服务，也不能把它对子任务历史的局部摘要当成外层消费者会话摘要。若当前依赖版本会对执行器局部历史自动压缩，需明确配置局部预算与隔离范围，确保不回写消费者全局摘要、授权或业务事实；不重复实现另一个全局摘要循环。

已根据现有部署源码与历史验收证据核实，当前 Qwen3-8B 服务总窗口为 8192 tokens，原接口输出预算默认 1024、允许 1–2048；新退款演示各节点的具体输出预算及框架依赖版本尚未定稿。因此不直接继承另一计算演示的依赖或 SDK 默认压缩阈值。

## 6. 摘要数据契约建议

实现时使用具名 `ConversationSummary` 模型，至少包含可信消费者 ID、会话 ID、摘要版本、覆盖的原始消息 ID 区间、摘要正文和生成事件 ID。字段约束在模型边界校验，覆盖区间是否属于该消费者及会话、是否越过未完成交互，由能访问真实消息与图状态的业务层验证。

摘要与原始聊天一并持久化到 MySQL，但分别保存。只在摘要生成、来源区间和预算检查通过后更新当前有效摘要；失败不覆盖上一份有效摘要，也不改变退款业务状态。跨进程恢复时同时恢复摘要版本、覆盖范围和近期消息，避免同一段历史重复或漏装。

## 7. 失败与可观察性

摘要生成失败时，可继续使用仍能装入预算的已验证上下文；如果无法保留当前请求所需信息并满足模型窗口限制，应明确说明本轮无法继续，保留原文和业务记录，不靠无提示截断来执行退款。这一失败边界已获用户确认。

过程日志记录压缩触发、模型输入预算、压缩前后估算 token、摘要版本和覆盖范围、保留近期回合及失败原因，不记录模型逐字内部推理。消费者通常只看到业务回答；涉及本轮停止时给出简短说明。

## 8. 已确认决定与实现细化

- 用户已确认按实际 token 预算自动触发“较早历史摘要 + 近期完整消息 + 独立结构化状态”，由外层 LangGraph 统一管理。
- 用户已确认聊天中的长期偏好查看、更正、删除与最新明确指令优先；摘要本身不形成长期偏好。
- 长期偏好具体执行边界见[存储与记忆设计](storage-memory.md)。用户已确认重启只恢复历史与待办，不自动继续退款；显式重置清理本演示的摘要、会话、偏好与模拟业务数据，保留 Milvus 政策索引，其他演示数据独立。

模型服务总窗口已知，具体阈值仍取决于节点的输出预留和实际序列化输入占用，中间件版本选择待实施基线确认；具体 token 数值、摘要长度和原文分段读取属于受已确认约束限制的实现选择，不用额外扩大为业务需求。

## 9. 已核对的预算事实

现有 Qwen 服务源码（`D:/Redemption/Redemption/K8S/qwen3-8b-bge-m3-plan-20261118/payload/qwen3_serve.py:128`）配置 `max_model_len=8192`；`max_num_batched_tokens=2048` 是调度配置，不等于总上下文只有 2048。历史超长输入证据（`D:/Redemption/Redemption/K8S/qwen3-8b-bge-m3-plan-20261118/evidence/invalid-qwen-length.json:6`）显示 8513 输入 tokens 被 8192 窗口限制拒绝，这不是本轮复测。

输入预算按“实际序列化输入 token + 本次输出预留 + 边界余量不超过 8192”计算。若本次预留输出 1024，则扣除边界余量前最多可有 7168 输入 tokens；该数字仅为预算示例，不是本稿已选定的压缩触发阈值，输入还必须计入实际序列化的系统规则、工具定义和框架模板。

现有独立计算演示锁定 LangGraph 1.2.22 / DeepAgent 0.7.38，但退款新演示并未明确采用相同锁定基线。原生工具 / Schema 服务的对接状态以[部署基线](model-selection.md)和[接口设计](integration-contracts.md)当前记录为准；协议验收不能代替完整退款或上下文压缩容量验收。本轮未执行模型推理、远端 tokenizer 或模型服务修改。
