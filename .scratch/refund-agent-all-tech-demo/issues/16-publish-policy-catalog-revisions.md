# 16 建立政策发布目录并支持多文档版本切换

**Status:** ready-for-agent

**Blocked by:** [15 移除 Host 的政策文件依赖](15-remove-host-policy-file-dependency.md)。

## 目标

维护者可以独立发布并切换任一退款政策文档的版本。新调查采用最新生效版本，已开始的调查沿用其政策版本快照，政策发布可独立于 Host 部署。

## 范围

交付 MySQL 政策发布目录、修订记录、显式发布命令及 MCP 的运行时版本选择，复用 15 的工具契约。支持同编号条款分属多份文档，按完整条款身份保留检索候选。正文去重作为后续优化。

## 涉及的契约

- 发布命令接收权威源文档及明确版本，FAQ 以问题和答案独立录入。FAQ 与正式条款分别作为可检索条目，答复出处来自本轮命中的条目。各文档支持独立更新。
- 新版本先完整写入 Milvus，按版本读回比对条目集合及内容，并验证正常检索。随后以 MySQL 事务提交该文档的生效版本及新的目录修订，保留其他文档版本。该文档的生效版本若被另一项并发发布改变，本次报告冲突。
- 发布记录可辨别版本是否曾经生效。重试前确认该版本从未生效且上次写入已结束，同版本清理和写入串行执行。仅删除该文档该版本的残留，用强一致查询确认清空，再按完整原件重发。首次生效前允许修正原件并保留版本号，首次生效后通过新版本修改或删除条款。切换回执不明确时先核对发布记录再恢复。
- MCP 将目录修订号作为政策版本快照的标识，用于所有本轮政策读取。修订无效或无法读取时按政策服务故障处理。读取身份继续使用配置文件中的 `mcp.read_token`。
- 发布命令记录发布者对资格行为的确认。现有代码继续计算退款资格，演示退款政策提供对应出处。改变资格的版本与同版本的结构化规则一起生效，结构化规则实现在本票之后另行交付。 [主设计](../spec.md#5-rag-文档与检索流程) · [数据库设计](../database-design.md) · [ADR-0010](../../../docs/adr/0010-refund-policy-publication-and-evidence.md)

## 验收标准

- [x] 发布两份均有 `RF-003` 的政策文档，其中包含一条只有问答的 FAQ。确认该 FAQ 在适用时可直接回答普通咨询。同名条款的检索及引用按文档、版本和编号区分。订单资格从演示退款政策的对应版本取依据。
- [x] 在一轮调查首次检索后只更新一份文档。旧调查的语义补查沿用原目录修订，新调查使用新目录修订，其他文档的生效版本一致。新版删除某条条款时，该条款退出新调查的检索范围，已生效的旧版本仍可支持旧调查。
- [x] 注入部分写入、写入后验证失败或切换回执中断。旧生效版本在新版本完成切换前继续提供查询。确认某版本从未生效后，使用同一版本号清理并全量重发，验证没有残留条目。曾经生效的版本在重试中仍保持可追溯，且并发切换冲突可以识别。
- [x] 用同一 Host 实例在政策更新前后完成查询，核对其工具契约与引用格式一致。发布记录包含资格确认，声明会改变资格的版本在同版本规则未就绪时保持未生效。

## 验证方式

在隔离的 MySQL 和 Milvus 验收环境验证发布、重试、并发和切换，用运行中的 Host 与独立 MCP 进程核对首轮检索和正式条款语义补查。在 `evidence/` 记录发布结果、目录修订和回执证据。
