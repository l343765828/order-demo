# 10: 维护核对关闭旧提交并允许消费者明确重新办理

**Status:** ready-for-agent

**Blocked by:** [08 多轮授权](08-manage-multiturn-refund-authorization.md)、[09 重复提交与回执核对](09-reconcile-duplicate-and-lost-receipts.md)。

## 目标

维护人员能确认未决提交的实际结果，在查无退款且能阻止旧请求执行时关闭提交。随后消费者可按当前会话的明确指令重新办理。

## 范围

交付独立演示维护命令，完成已核实结果的终态落库、对迟到请求的防护，以及原会话恢复待办和新会话新申请两条业务路径。维护命令仅在管理入口可用。

## 涉及的契约

- 维护事务与退款事务共用锁顺序，先以 `idempotency_key` 锁提交记录，再锁对应订单。事务内发现已有退款则关联原单并记 `succeeded`；查无退款则记 `closed_no_refund`。终态不因迟到回执被覆盖。
- 旧提交关闭后，原会话引用本次明确继续的用户消息，新会话引用明确指定订单的本次办理消息。均重查订单、重检 RF、核对本次授权和保存最终政策核验事件，生成新的幂等键。 [数据库设计](../database-design.md#维护核对与恢复) · [ADR-0007](../../../docs/adr/0007-refund-unconfirmed-dispatch.md) · [ADR-0008](../../../docs/adr/0008-refund-authorization-per-dispatch.md) · [ADR-0009](../../../docs/adr/0009-refund-policy-evidence-before-dispatch.md)

## 验收标准

- [ ] 维护命令核对旧提交。已有退款时返回并关联原单；无退款时同一事务关闭旧提交并释放唯一约束。再次运行返回一致终态。读取工具的查无记录本身不会关闭提交。
- [ ] 对真实并发交错分别测试维护先锁和写入先锁。维护先关闭时，迟到的旧键写入和回执均不能创建退款或翻转终态。写入先成功时，维护返回原退款，不能错误关成无退款。
- [ ] 分两套无退款关闭样本验证原会话明确继续、新会话明确指定订单办理。各自只在新核验通过后发送新键，并引用本会话本次用户原文；原键、旧授权、旧政策证据均不沿用。政策故障或订单状态改变仍阻止新退款。
- [ ] 未决期间两条路径都先核对旧结果并继续拦截。关闭或重启不会自行发起办理，新会话只说“继续”先澄清。消费者 CLI 和调查工具无法调用维护入口。

## 验证方式

围绕提交行锁设置交错屏障，把真实 MCP 写请求延迟至维护提交之后，再交换顺序重跑。使用隔离种子分别执行两条恢复路径，查询终态、授权消息、证据事件、幂等键及实际退款计数。
