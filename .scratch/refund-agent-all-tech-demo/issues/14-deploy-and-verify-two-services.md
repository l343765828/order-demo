# 14: 部署两个退款应用并完成首版联合验收

**Status:** ready-for-agent

**Blocked by:** [13 演示数据重置](13-reset-only-demo-data.md)。目标环境还需有批准的发布窗口、可达的依赖及演示数据操作权限。

## 目标

在目标环境以独立 Host 和 MCP Server 提供 CLI 演示，用一次正常办理及代表性故障回归证明首版设计可运行。

## 范围

交付独立部署单元和服务入口，配置现有 MySQL、Milvus 与自托管三模型，通过管理入口初始化演示数据和发布政策，再执行联合验收。沿用前序票交付的实现与验证脚本。

## 涉及的契约

- `refund-agent` 与 `refund-mcp` 两个独立应用，CLI 访问 Host。两应用使用公共 MySQL 配置、独立进程连接池及受控 MCP 凭据。Streamable HTTP 连接仅在有效 Client 生命周期内使用。
- 共享追踪字段关联会话、模型调用 ID、MCP 请求、检索事件、政策证据和退款幂等键。部署方式、密钥注入及运行验证按目标环境执行。 [主设计](../spec.md) · [MCP 接入](../mcp-integration.md) · [模型部署基线](../model-selection.md) · [ADR-0006](../../../docs/adr/0006-refund-agent-mcp-service-boundary.md)

## 验收标准

- [ ] 两个独立部署单元通过目标环境连接到所需依赖，验证 MySQL 版本和 checkpoint 实测基线。MCP 运行时发现四个约定工具，独立检查读取身份无法写入。普通启动保留已有数据，不触发重置或退款重放。
- [ ] 用目标环境 CLI 实跑本人查单、资格咨询、多轮明确办理和查看原结果。成功办理留存五项技术与真实跨进程 MCP 的调用证据，以及政策事件 → 提交 → 模拟退款的真实追踪链。
- [ ] 用受控数据或批准的故障注入复跑重排故障、政策核验事件不可用、并发重复、回执丢失、维护关闭与迟到请求、重启无重放、显式重置保留政策索引。归档每个场景结果与实收写调用计数。
- [ ] 记录锁定依赖、用例运行方式、发布配置引用、关键节点耗时和实际 token 用量。用接近窗口的 DeepAgent 请求验证模型容量并记录可取得的峰值资源数据。验收证据中不包含服务密钥。

## 验证方式

在获得授权的目标环境从 CLI 和维护入口运行联合验收，按追踪标识核对 Host、MCP、政策检索和实际业务记录。记录部署标识、依赖版本、操作窗口、故障注入结果和未通过项。
