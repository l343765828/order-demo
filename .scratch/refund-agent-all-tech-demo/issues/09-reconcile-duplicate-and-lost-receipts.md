# 09: 并发重复提交、回执丢失和重启只读核对

**Status:** ready-for-agent

**Blocked by:** [07 首次模拟退款](07-submit-one-mock-refund.md)。

## 目标

同订单即使并发申请、调用回执丢失或服务重启，也最多生成一笔成功退款。已有结果可以返回，尚无法确认时可明确告知并跨会话拦截该订单。

## 范围

完成提交冲突处理、按原提交核对并持久保存状态、故障注入及进程重启恢复。维护事务主动关闭旧提交及获准后的重新办理由 10 实施。

## 涉及的契约

- `refund_dispatches` 状态 `pending`、`unconfirmed`、`succeeded`、`closed_no_refund`；`blocking_order_id` 保持同订单至多一条未决。退款唯一性及原执行键由 `refunds` 保证。
- `get_refund_result(order_id, business_ref=None)` 和 `RefundLookupResult`。按同消费者／订单核对，已有业务标识仅用于关联。按原键和期望前态处理回执，终态单向保持。查无记录或查询不可用不能推断旧提交已无退款。
- 重启恢复历史与待办，业务事实按 MySQL 和只读 MCP 结果确认。恢复图、重连、协议协商或 SDK 自动回合不得重发写调用。 [数据库设计](../database-design.md#提交记录状态) · [MCP 接入](../mcp-integration.md#8-故障重启和重置) · [ADR-0007](../../../docs/adr/0007-refund-unconfirmed-dispatch.md)

## 验收标准

- [ ] 两个同消费者会话针对同订单并发生成不同幂等键，在真实 MySQL 用屏障证明只有一条未决提交获准写入，成功退款仅一行；竞争方触发已退款返回原结果或结果待核对。并发申请另一合格订单不受该订单的限制。
- [ ] 在 MCP Server 已提交退款事务后丢掉回执，Host 先发只读核对，取得并关联原退款单。再次办理（含新会话）返回原编号和金额，原退款幂等键不变。同键幂等回执不生成第二行，写调用没有自动重发。
- [ ] 在请求尚未得到可确认结果时分别返回查无记录与查询不可用，Host 提示结果待核对并保留未决。原会话明确继续与新会话明确办理均先核对旧记录，未决期间无第二条新提交或写调用。政策重排及政策证据持久化同时不可用时，这条核对链仍可执行。
- [ ] 在保存提交后发送前、MCP 提交后回执前、收到回执后 Host 更新前终止进程。重启 Host 或 MCP Server，不产生任何自动退款写调用；可恢复历史与待办，按明确请求核对真实结果。区分明确未发／回滚与尚不能确认的状态；仍未决的旧提交持续拦截。

## 验证方式

运行真实双会话并发测试，代理注入断连、提交后丢回执和协议重连，按故障点终止并重新启动进程。核对 MCP Server 实际收到的写调用数，检查 `refund_dispatches`、`refunds`、原单号及只读工具证据。
