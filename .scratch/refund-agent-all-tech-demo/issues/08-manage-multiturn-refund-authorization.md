# 08: 支持多轮补单、取消、换单与当前会话办理授权

**Status:** ready-for-agent

**Blocked by:** [07 首次模拟退款](07-submit-one-mock-refund.md)。

## 目标

消费者能在当前会话补齐订单号、暂停调查去咨询、取消或更换订单，退款提交始终引用仍有效的本次办理授权。

## 范围

扩展会话状态与原始消息关联，串行处理同会话取消、换单与提交创建。已保存提交按同一提交行撤销授权。业务执行按同步调用边界处理；维护关闭和旧提交恢复由 10 落实。

## 涉及的契约

- `ConversationDecision`、`AuthorizedRefundIntent`、会话结构化状态、`conversation_messages`、`refund_dispatches.source_message_sequence`、`revoked_at`。两轮补单时提交的来源为明确办理消息，授权核验事件通过 `trace_id` 同时关联补单消息。
- 未决提交即使授权已撤销，仍拦截同一订单，直至核对或关闭；已成功的退款仍可读取。 [主设计](../spec.md#41-理解意图与会话更新) · [数据库设计](../database-design.md#关系与退款写入) · [ADR-0008](../../../docs/adr/0008-refund-authorization-per-dispatch.md)

## 验收标准

- [ ] “我要退款”先追问并持久保存会话待办，无提交；同会话补 `DEMO-1001` 后按实际事实重新调查并正常办理，提交引用第一条明确办理消息，追踪事件可找到本次补单消息。
- [ ] “我的订单能退吗”后仅补 `DEMO-1001`，完成只读资格咨询；办理待办期间插入政策问题，只回答咨询并保留待办，收到明确继续才恢复。歧义、多笔订单、无当前会话待办时的单独“继续”均先澄清。
- [ ] 取消后仅补订单号不创建授权。换单时丢弃旧授权、订单事实、计划和政策依据；仅在本会话对新订单有明确办理指令时进入新调查。新会话不能从旧会话借用授权。
- [ ] 同会话制造取消／换单与创建提交的竞争，状态按串行顺序生效。对已保存且尚未执行的提交写入 `revoked_at` 后，迟发写调用无法首次写入，未决状态仍拦截；已经成功的结果无法通过取消撤销。

## 验证方式

执行同义措辞、多轮插话、取消后补单、换单和新会话的对照脚本，检查消息序号、授权和写调用计数。在提交保存位置设置同步屏障，交错执行会话命令，核对行锁与退款结果。
