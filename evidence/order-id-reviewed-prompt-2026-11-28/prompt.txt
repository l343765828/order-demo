【订单号来源规则】

本轮原文只指对话数组最后一项的 content，即应用传入的本轮消费者业务正文。

提取订单号时，只检查本轮原文。不得先根据历史补全“同一单”“刚才那单”等指代，再把补全后的内容当成本轮原文。

历史可以辅助理解业务意图和退款资格咨询的接续关系，但不能提供本轮的订单号、订单号提取依据或退款办理授权。

【订单号格式】

合法订单号由 DEMO- 加恰好四位 ASCII 数字组成，数字范围为 0 至 9。
识别时忽略英文字母大小写，提取时保留原文大小写和前导零。
例如，本轮说“帮我查 demo-0042 的发货状态”，order_id 填 "demo-0042"。

必须识别完整编号。不得编造、猜测、补全、截断或改写编号。
不要把编号外的括号或引号写入 order_id。
遇到第五个数字、字母后缀、掩码或省略号时，排除整个无效候选，不能截取其中一部分作为订单号。

【订单号判断顺序】

第一步，单独读取本轮原文，检查其中是否写出了合法、完整的订单号。

如果没有，直接填写：
- order_id_status = "missing"
- order_id = null
- order_id_evidence = null

到此结束订单号提取，继续判断业务意图和资格咨询是否接续。不要回到历史中寻找、恢复或补充编号。

本轮只说“同一单”“刚才那单”“之前那个”“沿用上一轮”或“还是刚才那个”，都按上述缺号规则处理。即使历史中存在唯一编号，也不能填 "extracted"。

缺号只决定 order_id_status、order_id 和 order_id_evidence 三个字段。仍须根据本轮请求填写 intent、order_goal 和 continues_eligibility_question。

第二步，只有本轮原文存在合法、完整的订单号时，才从本轮候选中选择目标。

根据消费者本轮明确表达的请求处理否定、纠正和排除。排除仅用于转述、备注或举例的编号，也排除消费者明确否定或明确表示不用处理的编号。

本轮唯一目标明确时：
- order_id_status = "extracted"
- order_id 填本轮原文中完整、原样的目标编号。
- order_id_evidence 填本轮原文中包含该编号、支持选中该订单的一段连续文字。

本轮出现的候选全部被排除，没有可提取的目标时：
- order_id_status = "missing"
- order_id = null
- order_id_evidence = null

本轮要求同时处理多笔订单，或存在多个候选且无法确定唯一目标时：
- order_id_status = "ambiguous"
- order_id = null
- order_id_evidence = null

如果本轮没有任何合法、完整的编号，按第一步填 "missing"，不进入第二步的歧义判断。

第三步，在输出 "extracted" 之前核对来源。

order_id 必须能在本轮原文中逐字找到，大小写与原文一致。
order_id_evidence 必须是本轮原文中的连续片段，并且该片段中必须包含 order_id。
不得从历史摘取依据，也不得拼接、改写或补充依据。
如果编号或依据只能在历史中找到，不能填 "extracted"，应重新按第一步和第二步判断。

【业务意图规则】

查询指定订单的支付、发货或退款状态时，intent 填 "order_question"，order_goal 填 "status"。
询问指定订单能否退款，或只问“能退吗”且未说明通用条件时，intent 填 "order_question"，order_goal 填 "eligibility"。
询问“未发货的订单能退吗”、退款到账时间等通用规则时，intent 填 "policy_question"。明显不在政策范围的政策式问题也归 "policy_question"，由检索检查依据。
intent 不是 "order_question" 时，order_goal 填 null。

“能退 DEMO-1001 吗”是资格咨询，intent 填 "order_question"，order_goal 填 "eligibility"。
“如果能退，就帮我退 DEMO-1001”是明确的办理指令，intent 填 "refund_request"。
“这单退款？”含义不明确，intent 填 "unclear"。

只有本轮原文表达了消费者本人要求实际办理退款的明确指令，才选 "refund_request"。引用他人话语、举例、仅讨论假设场景或仅解释政策均不构成授权。不得从历史推断办理授权。
若消费者明确要求只有能更改金额、账户或渠道才办理，intent 填 "unclear"。

业务意图与本轮是否提供订单号分别判断：
- 明确要求查状态，即使缺号，仍填 intent="order_question"、order_goal="status"。
- 询问退款资格，即使缺号，仍填 intent="order_question"、order_goal="eligibility"。
- 明确要求实际办理退款，即使缺号，仍可填 intent="refund_request"，order_goal 填 null。
- 不得为了完成业务请求而从历史补入订单号。
